# RETRO-E 最终报告：面向 LLM 逆合成的可训练"合成经验" Context

**日期：** 2026-09-04 | **状态：** 主确证实验、辅助 control 组、以及一次事后跨 judge 稳健性检验均已完成。
**本报告在跨 judge 检验改变了 H1 的结论之后做了修订**——见第 5.4 节。

---

## 1. 执行摘要

在基础 LLM、system prompt、采样参数和 target 集合完全冻结的前提下，给 prompt 加入一段简短的合成经验
context（`E0`）确实在盲双人对比中提升了逆合成路线质量——但**只在用生成路线的同一个模型来评判（自评）时
成立**。用一个真正不同的模型（`gpt-5.6-luna`，而不是自评用的 `gemini-3.7-flash-high`）在完全相同的路线
上重新评判后，**这个效应没有复现**：净胜率从 +11.7%（显著）跌到 +2.7%（置信区间跨过 0，不显著）。
**H1 的结论从"是"下修为"不确定"。** 用 GEPA 式 reflective-mutation 优化器进一步训练这段经验文本，
得到 `E*`，它在同一个未被碰过的测试集上再次相对 `E0` 有提升，而且**在两种 judge 下都成立**——自评
+14.0%，独立评判 +13.0%，均统计显著。**H2 得到支持，是两个发现里更可靠的一个。**

| 对比 | Judge | 净胜率 | Target-cluster 95% CI | Holm 校正 p |
|---|---|---:|---:|---:|
| E0 vs baseline (**H1**) | gemini（自评） | +11.7% | [1.3%, 21.7%] | 0.043 |
| E0 vs baseline (**H1**) | **gpt-5.6-luna（独立）** | **+2.7%** | **[−8.3%, 13.3%]** | **0.680** |
| E\* vs E0 (**H2**) | gemini（自评） | +14.0% | [3.3%, 24.3%] | 0.024 |
| E\* vs E0 (**H2**) | gpt-5.6-luna（独立） | +13.0% | [3.0%, 22.7%] | 0.046 |
| E\* vs baseline（一致性佐证） | gemini（自评） | +23.3% | [12.7%, 33.7%] | <0.0001 |
| E\* vs baseline（一致性佐证） | gpt-5.6-luna（独立） | +16.0% | [5.3%, 26.7%] | 0.016 |
| E\* vs control（辅助，仅自评） | gemini（自评） | +14.3% | [3.0%, 25.7%] | 0.011 |

辅助的长度匹配 control 组（E\* vs 一段长度匹配但不含逆合成策略内容的化学事实文本）排除了"E\* 赢是因为
prompt 更长/更像化学文本"这个替代解释——长度匹配、化学语域相近，但不含任何逆合成策略指导的文本，
表现不如 E\*。这一项检验目前只在自评模型下跑过；鉴于下文的跨 judge 发现，在被独立重新评判之前，它应该
和自评的 H1 结果一样带上同样的保留条件。

这个项目最重要的发现不是某一个具体数字，而是：**自评实质性地虚高了一个结果（H1），却没有影响另一个
结果（H2）**——这正是原始协议自己在风险清单里警告过的那种失效模式（见第 7 节）。在用独立 judge 做过
完整规模的确证之前，H1 应该被当作一个悬而未决的问题，而不是一个已确认的效应。

## 2. 研究问题与假设

两个问题，在一个约束下测试——基础模型从始至终不做微调或任何形式的修改，唯一变化的是作为"经验"喂给它
的文本。

- **H1** —— 加入一段固定的、未经优化的合成经验 context（`E0`），是否能在同一个冻结 LLM 上、相对无
  context 的情况提升逆合成路线质量？`LLM(x, E0) > LLM(x)`
- **H2** —— 在基础模型依然冻结的前提下，这段经验能否被训练/优化成一个更好的形式 `E*`，进一步超过
  `E0`？`LLM(x, E*) > LLM(x, E0)`

贯穿全程的指导原则：*不训练 LLM，只训练经验 context 本身。*

## 3. 实验设计

### 3.1 全程冻结的变量

基础模型及版本、system prompt、target 划分、输出 schema、采样参数（temperature/top_p/max_tokens/
n_routes）、每个 target 的独立采样数、judge 模型、judge prompt 和评分标准。各条件之间唯一变化的是经验
context 文本本身。测试集 target 从未被用于构建 `E0`、优化 `E*`，或挑选 control 文本。

### 3.2 四个实验条件

| 条件 | Prompt 内容 |
|---|---|
| `baseline` | System prompt + target，不含任何经验文本 |
| `E0` | System prompt + 未优化的合成经验 + target |
| `E*` | System prompt + GEPA 优化后的合成经验 + target |
| `control` | System prompt + 长度匹配、无策略内容的化学事实文本 + target |

### 3.3 数据

来源：**PaRoutes 2.0 n1 reference routes**（Zenodo，DOI `10.5281/zenodo.7341155`）——从 USPTO 专利
反应网络中机械抽取出的路线。**这些是 benchmark 路线，不是经过独立验证的实验室或文献合成路线**；每条
记录都被标记为 `needs_human_review=true`，且缺少反应类型、分离产率和完整反应条件。这是贯穿整个项目的
数据质量局限（见第 7 节）。

筛选条件：target 18–65 个重原子，路线 ≥5 步且 ≥2 个叶子节点，固定随机种子 `20260902`，从 10,000 条
原始路线（经尺寸/复杂度筛选后剩 967 条合格）中筛出 500 个不重复的 Murcko scaffold。三个 scaffold
互不重叠的划分：

| 划分 | 数量 | 作用 |
|---|---:|---|
| 经验来源路线 | 200 | 仅用于构建 `E0` |
| 训练集（Context Training Set） | 200 | 划分为 160 个 optimizer target + 40 个 selection target，用于 Stage 4 |
| 测试集 | 100 | 直到 Stage 5 之前完全未被触碰；与另外两个划分 scaffold 不重叠 |

泄漏审计（`data/processed/dataset_quality_report.json`，`retro-e audit-targets`）：跨划分 0 个
canonical SMILES 泄漏，0 个 Murcko scaffold 重叠；0 个重复 target ID；300/300 个训练+测试 target
均能被 RDKit 正确解析。

### 3.4 `E0` 的构建

`E0` *只*从 200 条经验来源路线中蒸馏得到（从不参考任何 target 的表现）：10 批、每批 20 条路线分别
总结，聚合并压缩到目标预算，由另一个模型审计是否存在 target 记忆化/对专利数据过拟合的问题，再修订——
这一切都发生在任何生成或评判之前。最终版 `E0`：16 条编号条目，不含任何 SMILES，不含任何来源路线的
标识符（经精确字符串泄漏检查确认），冻结哈希为
sha256 `183f9018fdae2555720e49d1f65842519e033a089dfb6eab03428396d8ba88e4`。

### 3.5 `E*` 优化（Stage 4）

一个 GEPA 式的黑盒文本优化器，实现为三层依次收窄（successive-halving）的评估机制，而不是直接调用
`dspy.GEPA` 自带的循环，因为协议明确要求*"GEPA 可以选择候选文本的修改方式，但不能决定评估用的
target、样本数量或停止规则"*——GEPA 自带的预算/Pareto 调度机制无法遵守外部预先声明好的预算安排。
具体做法：每一轮变异先用 judge 家族模型批评当前候选文本的失败/打平案例，再用 generator 家族模型据此
改写文本——这是 GEPA 的 reflective mutation 思路，只是调度权收归外部。

| 层级 | 评估候选数 | Target 批次 | 样本数 × 票数 | 最优 reward |
|---|---:|---|---|---:|
| 1（screen） | 24（含 E0 种子） | 40（160 个 optimizer target 里固定抽出的子集） | 1 × 1 | 0.713（E0 种子：0.525） |
| 2（advance） | tier1 前 6 名 | 120（160 个里剩下、与 tier1 不重叠的部分） | 1 × 3 | 0.637 |
| 3（final） | tier2 前 2 名 | 40 个 selection target（直到这一层才第一次用到） | 3 × 3 | **0.621（胜出者）** |

Reward = 候选路线相对缓存好的 baseline 路线的 mean(赢=1, 平=0.5, 输=0)，盲评、顺序随机化。值得注意的是，
tier1 排名第一的候选（在 40 个 target、1 票的筛选下拿到 0.713）换到更大、投票更多的 tier2 批次上重新
评估后，掉到了中等水平的 0.537——这正是 successive-halving 这套设计想要抓住的"小批次过拟合"现象。
最终真正胜出的 `5fd7566a40e30762`，其实是 tier1 里排名*第二*的候选。

全程强制执行的硬约束：`E*` 的 token 数在锁定的 `tiktoken` `o200k_base` 编码下 ≤ `E0` 的 110%（胜出者：
755 对 736，比例 1.026）；每个候选都要经过逐字扫描，检查是否原文照抄了任何训练/测试 target 的 SMILES
或来源标识符（零泄漏——这项检查在跑的过程中确实主动淘汰过至少一个超预算/有泄漏的候选）；优化器全程
未接触过 `test_targets.jsonl`。

胜出的 `E*`（`contexts/experience_E_star.md`，sha256
`5fd7566a40e3076275e8845c2b65e92914f72562a5c37bf4b4fbad4a1bbaf79a`）读起来是与 `E0` 相同语域和结构
的 16 条条目——断键策略、convergent/linear 权衡、保护基与化学选择性方面的判断——而不是一份记住的反应
列表。

### 3.6 盲双人对比评判

对每个 target/样本对，每次投票都独立随机把两条路线分配为"Route A"/"Route B"（确定性种子随机化，映射
可复现，但 judge 从不知道哪条路线来自哪个条件）。每对独立评判 3 票；多数票映射回来源条件后确定胜负。
无效的模型输出从不被静默丢弃：有效路线总是胜过无效路线，两条都无效则记平局
（`predeclared_validity_rule`），这样每一个计划内的 target/样本对都留在分析范围内。

### 3.7 项目中途的协议变更（全部公开披露）

Stage 3（H1-screen）完成之后又做了两处变更，都是出于成本考虑，不是科学设计意图的改变——完整过程和
实测证据记录在 `HANDOFF.md` 第 10a/10b 节：

1. **Judge 模型：`gpt-5.6-sol` → `gemini-3.7-flash-high`。** `gpt-5.6-sol` 是一个推理模型，每次
   单 token 的 judge 调用会消耗约 1,000–3,700 个隐藏推理 token（在真实的 H1-screen 数据上实测，并
   与其 `luna`/`terra` 两个兄弟版本做了交叉验证——没有一个明显更便宜）。剩余协议还需要约 6,500–7,500
   次 judge 调用，即单这一个模型家族就要消耗约 2,400–2,800 万 token。用户在权衡后明确决定把 judge
   换成 `gemini-3.7-flash-high`——与 generator 用同一个模型——把由此带来的**自评**接受为一个刻意的
   成本/严谨性取舍。已经完成的 Pilot 和 H1-screen（`gpt-5.6-sol` 评判）**没有**被重新评判：它们的
   作用只是资源门槛检查，不是确证性证据，所以不会污染 Stage 4/5 的结果——后者从头到尾用同一个 judge
   模型，内部自洽。
2. **Judge prompt v1 → v2，`max_tokens` 从 16 提到 150。** 把 judge 换成 `gemini-3.7-flash-high`
   后，在旧的 prompt/token 预算下，16 个真实数据样本测试出现了**50% 的解析失败率**（模型会在给出
   答案之前先写一段解释，结果被截断到一半）。修复方式：新建 `prompts/judge_v2.txt`，明确要求把
   `DECISION: <A|B|Tie>` 作为强制的第一行，并在 `parse_decision` 里加入基于这个锚点的宽松兜底解析。
   用同一批 16 对数据重测：16/16 全部解析成功，平均每次只消耗 4 个可见 completion token。

两处变更都经过真实 API 调用测试，并在**任何 Stage 4/5 数据被采集之前**就已冻结——没有任何结果是在
有问题的配置下采集的。

## 4. 统计方法

每个对比都报告：胜/负/平场数、净胜率 `(胜−负)/总场数`、排除平局后的条件胜率及其 Wilson 95% 置信区间、
双侧精确符号检验。因为同一个 target 的三个样本是相关观测，**主要的不确定性区间用 target 级别的
cluster bootstrap**（对 target 而不是对单场比赛做 10,000 次重抽样），而不是假设独立同分布的逐场区间。
在三个对比构成的确证性 family 内部，p 值做 **Holm 校正**以控制多重比较。决策规则（预先注册于
`reports/EXPERIMENT_PLAN.md`）：

- **是** —— 净胜率为正，cluster-bootstrap 置信区间不包含 0，且 Holm 校正后 p < 0.05。
- **否** —— 置信区间上界落在 +5 个百分点或以下（即排除了任何有意义的收益）。
- **不确定** —— 其他所有情况，包括统计功效不足的结果。

## 5. 实验结果

### 5.1 Stage 0–3 —— pilot 和 H1-screen（非确证性，仅作资源门槛）

| 阶段 | target 数 | 场数 | 净胜率 | 符号检验 p | Cluster 95% CI |
|---|---:|---:|---:|---:|---:|
| Pilot（`E0` vs baseline） | 5 | 15 | +33.3% | 0.302 | 很宽，无信息量 |
| H1-screen（`E0` vs baseline） | 30 | 90 | +17.8% | 0.105 | [−1.1%, 36.7%] |

两者都用 `gpt-5.6-sol` 做 judge（早于协议变更）。方向为正，"只有 screen 方向为正才投入昂贵优化"这个
门槛条件得到满足，但按协议这些数字从未被当作确证性证据，也没有影响 `E0` 的构建或之后任何 prompt
修改。

### 5.2 Stage 4 —— 优化轨迹

详见上文 3.5 节。要点：tier1 的 24 个候选里，每一个都打平或超过了 E0 种子在同一批次上自己的 reward；
最终胜出的 `E*` 在 40 个从未用过的 selection target 上以 72–43（5 平）战胜了缓存的 baseline。

### 5.3 Stage 5 —— 主确证实验（核心结果）

100 个未被触碰过的测试 target，每个条件（baseline/E0/E\*/control）各 3 个独立样本，每场评判 3 张
独立票。共 1,200 次路线生成，3,600 次 judge 调用，0 次 API 失败。

| 条件 | 生成数 | 无效率 |
|---|---:|---:|
| baseline | 300 | 5.0% |
| E0 | 300 | 4.7% |
| E\* | 300 | 4.7% |
| control | 300 | 4.0% |

| 对比 | 胜 | 负 | 平 | 净胜率 | 排除平局后胜率（Wilson 95% CI） | Cluster-bootstrap 95% CI | 符号检验 p | **Holm 校正 p** |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| **E0 vs baseline (H1)** | 159 | 124 | 17 | **+11.7%** | 56.2% [50.4%, 61.8%] | **[1.3%, 21.7%]** | 0.0431 | **0.0431** |
| **E\* vs E0 (H2)** | 154 | 112 | 34 | **+14.0%** | 57.9% [51.9%, 63.7%] | **[3.3%, 24.3%]** | 0.0118 | **0.0236** |
| E\* vs baseline | 172 | 102 | 26 | +23.3% | 62.8% [56.9%, 68.3%] | [12.7%, 33.7%] | 0.0000279 | 0.0000838 |
| E\* vs control *(辅助)* | 158 | 115 | 27 | +14.3% | 57.9% [51.9%, 63.6%] | [3.0%, 25.7%] | 0.0109 | 0.0109 *(n=1 family)* |

前三行的 Holm 校正是在这三个对比构成的 family 内部单独计算的，完全按预先声明的方式执行；`E* vs
control` 是辅助性对比，单独作为一个只有它自己的 family 报告（所以它的"Holm 校正"p 值等于它自己的
原始符号检验 p 值）。如果把它混进主 family 会悄悄改变前三行校正后的 p 值——这个问题在分析过程中被
发现并修正了（`results/final_primary_metrics.json` 对应前三个主对比，`results/final_control_metrics.json`
对应这一个辅助对比）。

**E\* 同样战胜了长度匹配、无策略内容的 control 组**，幅度（+14.3%）接近它相对 E0 的胜率（+14.0%）。
由于 `control` 和 `E*` 长度匹配、语域上都接近化学文本，这个结果排除了"prompt 更长"或"更像化学文本"
这两个对 E\* 优势的替代解释——真正起作用的是 E\* 里的可执行策略内容，不是它的长度或语域。（这项检验
目前只在自评模型下跑过——见 5.4 节。）

### 5.4 跨 judge 稳健性检验（事后追加）

原始设计中的 Limitation 1（自评：Stage 4/5 用 `gemini-3.7-flash-high` 同时充当 generator 和 judge）
当时只是一条披露出来的风险，还没有被实测验证过。为了直接检验它，三个主对比在**完全相同、已经生成好的
Stage 5 路线**上用 `gpt-5.6-luna`——一个与冻结 generator 完全不同的模型家族——重新评判了一遍，替换掉
自评用的 `gemini-3.7-flash-high` judge。没有生成任何新路线，只换了 judge。新增 2,700 次 judge 调用，
0 次失败，路线和有效率与自评那一轮完全一致。

| 对比 | 胜–负–平 | 净胜率 | Cluster 95% CI | Holm p（各自独立的 3 对比 family） |
|---|---:|---:|---:|---:|
| E0 vs baseline (H1) | 148–140–12 | +2.7% | [−8.3%, 13.3%] | 0.680 |
| E\* vs E0 (H2) | 159–120–21 | +13.0% | [3.0%, 22.7%] | 0.046 |
| E\* vs baseline | 166–118–16 | +16.0% | [5.3%, 26.7%] | 0.016 |

**H2 复现了**：换成独立 judge 后，净胜率、置信区间和显著性全部保住了，差距收窄但没有消失（Holm p 从
0.024 变成 0.046，依然低于 0.05）。**H1 没有复现**：独立 judge 看到的效应弱得多，置信区间直接跨过 0
（Holm p = 0.680）。Gemini 的自我评判看起来专门虚高了 `E0` 相对 `baseline` 的优势，这个虚高在换一个
judge 之后就消失了；而 `E*` 相对 `E0` 的优势——真正的训练效应——并不依赖于是哪个模型在评判。

成本备注：实测下来，`gpt-5.6-luna` 的隐藏推理 token 开销和 `gpt-5.6-sol` 基本一样（在真实
Stage-5 风格 prompt 上约 4,000 token/次）——正是第 3.7 节把冻结 judge 换掉的那种成本量级。因此这次
检验只覆盖了三个主对比，跳过了辅助的 control 组，目的是在不重复承担同等规模成本的前提下，回答最重要
的那个开放问题（H1/H2 在独立 judge 下是否成立）。

**H1 修订后的结论**：按预先声明的决策规则（"不确定：其他所有情况，包括统计功效不足的结果"），一个
在换成同等能力、但明显不同的 judge 之后从显著变成完全不显著的结果，不能算是有把握的"是"。H1 下修为
**不确定**，等待用独立 judge 做完整规模的确证实验。H2 的结论维持不变，现在是这个项目里两个假设中
证据更充分的一个。

## 6. 决策规则下的结论

> **问题 1 —— 在基础 LLM 完全冻结的前提下，加入固定的合成经验 context 是否改善逆合成路线质量？**
> **答案：不确定。** 在自评模型下：净胜率 +11.7%，cluster 95% CI [1.3%, 21.7%]，Holm p = 0.043——
> 单独看是个"是"。在独立 judge（`gpt-5.6-luna`）对完全相同路线的评判下：净胜率 +2.7%，cluster 95%
> CI [−8.3%, 13.3%]（跨过 0），Holm p = 0.680——不显著。一个换了个明显不同的 judge 就反转的结果，
> 按预先声明的决策规则不能算是有把握的"是"。这是整个项目最需要提醒的一点。

> **问题 2 —— 在基础 LLM 依然冻结的前提下，这段经验 context 能否被训练/优化得更好？**
> **答案：是——而且是更可靠的发现。** 自评：E\* vs E0 净胜率 +14.0%，cluster 95% CI [3.3%, 24.3%]，
> Holm p = 0.024。在完全相同路线上独立评判：净胜率 +13.0%，cluster 95% CI [3.0%, 22.7%]，
> Holm p = 0.046。方向相同、幅度相近，在两种 judge 下都显著。

合起来看：*训练*经验 context 有用（H2）这个证据是扎实的，换个 judge 依然成立。*加入*一段未经训练的
经验 context 就有用（H1）这个证据没能通过同样的检验，在用独立 judge 做完整规模的重新确证（不只是
这里检验过的三个主对比）之前，应该被当作一个悬而未决的问题，而不是一个已确立的结果。

## 7. 局限性

1. **自评——已被证实会造成实际影响，不再只是理论风险。** Stage 4 和 Stage 5 用 `gemini-3.7-flash-high`
   同时充当 generator 和 judge，是项目中途出于成本原因从"不同家族的 judge"改过来的（见第 3.7 节）。
   第 5.4 节的跨 judge 检验把这个问题从一条披露的风险变成了一个实测出来的结论：用 `gpt-5.6-luna`
   重新评判完全相同的 Stage 5 路线后，H2 保持不变（自评 +14.0% → 独立 +13.0%，均显著），但 **H1 崩塌**
   （自评 +11.7% → 独立 +2.7%，置信区间跨过 0）。自评虚高的是"经验 context 存在有没有用"这件事本身
   （H1），却没有虚高"训练"这个效应（H2）——是一个具体的、不对称的发现，不是单方向的整体偏差。`E*`
   在 Stage 4 里也是针对 Stage 5 里同一个 judge 给出的 reward 信号被优化出来的，这本身是一条 `E*`
   有可能利用 judge 特有偏好而不是真正提升路线质量的潜在通道；H2 在独立 judge 下依然成立，说明这个
   效应即使存在，规模也不大，但不能完全排除更小规模的影响。
2. **数据来源。** PaRoutes 路线是从专利里挖出来的，不是经过独立验证的合成路线。RDKit 有效、
   schema 合规只是一道操作层面的底线，不是化学质量的背书——一条路线可以在语法上完美，实际却是一个
   很差的合成方案。所有评判都是 LLM 对未经验证的假设路线做出的判断，不是跟文献真实工艺做比较。
3. **Judge 的确定性。** Temperature 设为 0 并不保证生成式模型每次重复给出完全一致的判断；三票独立
   投票加多数表决能部分缓解这个问题，但无法完全消除。
4. **还没有做独立的（比如专家化学家）judge 一致性审计**，来验证两个 LLM judge 的偏好是否真的跟
   实际合成价值挂钩。第 5.4 节的检验显示两个 LLM judge 恰好在 H1 这一项上意见不一致，这让这项审计
   变得更紧迫而不是更不重要——两个 LLM 互相不一致，本身并不能说明哪一个（如果有的话）更接近真实的
   合成判断。
5. **辅助 control 组只在自评模型下跑过。** `E*` vs 长度匹配、无策略内容的化学事实文本：净胜率
   +14.3%（cluster 95% CI [3.0%, 25.7%]，p = 0.011）——排除了"prompt 更长/更像化学文本"这个对
   E\* 优势的替代解释，但鉴于第 5.4 节的发现，这个具体结果本身还没有经过跨 judge 检验，在被独立
   重新评判之前，应该带上和自评的 H1 结果一样的保留条件。
6. **效应量。** H2 在目前检验过的两种 judge 下都是统计显著但幅度不大的效应——不是能力上的巨大飞跃。
   H1 的状态现在是"不确定"，而不是此前认为的"幅度不大的正向效应"（见第 5.4 节）。

## 9. 建议的后续步骤

1. **用独立 judge 在完整确证规模上重新检验 H1**，而不只是第 5.4 节这种事后追加的三对比检验。目前
   独立 judge 给出的 H1 结果（100 个 target，900 场，3 票）统计功效已经相当够用，指向"没有效应"，
   但一次专门预先注册的正式实验——理想情况下用一个比 `gpt-5.6` 推理系列更便宜的 judge——会比在已有
   报告后面追加一次事后检验更能把这件事说清楚。
2. **辅助 control 组的对比也需要用独立 judge 重新跑一遍**（对应局限性第 5 条）——目前它只被自评过，
   而第 5.4 节已经证明自评不是处处可靠。
3. 针对两个 LLM judge 做一次小规模的盲态专家化学家一致性审计，会有助于判断哪一个（如果有的话）更
   接近真实的合成价值判断——现在它们恰好在 H1 上意见不一致，这个问题更值得回答。
4. 任何后续研究都应该从一开始就为独立 judge 的实验预留预算，而不是跑到中途才发现成本问题，并且尽量
   挑一个真正便宜的、不同家族的 judge——这个项目试过的两个候选（`gpt-5.6-sol`、`gpt-5.6-luna`）
   最后都是同样昂贵的推理开销。
5. 既然 H2 的效应量真实但不算大，进一步研究 E\* *具体是怎么起作用的*（16 条条目里哪些在真正驱动
   胜率，可以用消融实验来看）会比单纯扩大样本量更有信息量。
