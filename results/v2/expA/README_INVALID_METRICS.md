# expA_metrics.INVALID.json 不是结果

该文件由 2026-09-14 被中断的 phase 2 运行写出，**其中的净胜率不构成任何证据**，
已重命名以防被误引。

中断原因：网关上游鉴权故障，两个 Gemini 模型同时返回
`HTTP 503 auth_unavailable: no auth available (providers=antigravity)`。
非配额冷却，非代码缺陷。

该文件为何不可用：

| 项 | 计划 | 实际 |
|---|---:|---|
| `R_empty vs R_E0` 配对 | 400 | **20**，且 20/20 由有效性规则判决 |
| `R_empty vs E0` 配对 | 400 | **21**，且 21/21 由有效性规则判决 |
| `E_star vs E0`（阳性对照） | 400 | **0，从未开始** |

「由有效性规则判决」意味着那些配对压根没有调用 judge —— 它们是一方路线无效、按预先声明的
规则自动定胜负的。因此 judge 实际产出的可用裁决接近于零。

阳性对照缺失这一点单独就足以否决全部解读：按设计，`E_star vs E0` 必须先在这 200 个全新
target 上复现 round-1 的 +0.13~0.14，否则整套装置不能被认为在测它当初测到的东西。

原始记录（`generations/`、`judgments/`）未受影响，append-only 且可续跑。恢复后重跑同一命令
即可补齐缺口：生成端已落盘 1310/1600，缺 E_star 的 288 次与另三条件各 1 次。
